# کلمه‌یاب فارسی (Persian Word Finder)

یک اپلیکیشن ساده و سریع React برای پیدا کردن کلمات فارسی معنی‌دار بر اساس:

- **حروف در دسترس** (مثلاً `ابکلم`)
- **بازه طول کلمه** (بین حداقل و حداکثر تعداد حرف)

مناسب برای حل پازل‌هایی مثل آمیرزا، جدول، اسکربل فارسی و بازی‌های کلمه‌سازی.

---

## ✨ ویژگی‌ها

- 🔍 جستجوی سریع روی صدها هزار کلمه فارسی
- 📏 فیلتر بر اساس طول کلمه (بازه قابل تنظیم)
- 🔤 بررسی دقیق تکرار حروف (هر حرف فقط به تعداد موجود در ورودی قابل استفاده است)
- 🇮🇷 رابط کاربری کاملاً راست‌به‌چپ با فونت **Vazirmatn**
- ⚡ بارگذاری یک‌باره دیکشنری و بهینه‌سازی با Bucketing
- 🧹 حذف خودکار کلمات تکراری از دیتاست
- 📦 بدون وابستگی به API خارجی — کاملاً آفلاین و رایگان

---

## 🛠️ تکنولوژی‌ها

- **React** (با Hooks)

## 📚 منبع دیکشنری

دیتاست استفاده‌شده در این پروژه از **فرهنگ معین** استخراج شده است:

> 🔗 [`hicte/moin`](https://github.com/hicte/moin)

فرهنگ معین یکی از معتبرترین فرهنگ‌های لغت فارسی است. دیتاست حاصل، کلمات را به صورت فایل‌های متنی ساده (هر کلمه در یک خط) ارائه می‌دهد و به همین دلیل برای پردازش در مرورگر بسیار مناسب است.

### چرا معین و نه دیتاست‌های بزرگ‌تر؟

دیتاست‌های عمومی بزرگ (مثل ۷۵۰ هزار کلمه‌ای) شامل کلمات تخصصی، املای اشتباه، اسم مکان‌ها و واژه‌های غیررایج هستند که برای بازی‌های کلمه‌سازی مناسب نیستند. فرهنگ معین تعادل خوبی بین **جامعیت** و **تمیزی** ارائه می‌دهد.

## 🚀 راه‌اندازی

### پیش‌نیاز

- Node.js نسخه ۱۸ یا بالاتر
- npm یا yarn

### مراحل نصب

```bash
# ۱. کلون کردن مخزن
git clone <your-repo-url>
cd persian-word-finder

# ۲. نصب پکیج‌ها
npm install

# ۳. اجرای dev server
npm run dev
```

سپس آدرس `http://localhost:5173` را در مرورگر باز کن.

### آماده‌سازی فایل دیکشنری

مطمئن شو فایل `words.txt` (استخراج‌شده از دیتاست معین) در پوشه `public/` قرار دارد. هر کلمه باید در یک خط جداگانه باشد:

```
آب
آبی
کتاب
مدرسه
...
```

## 🧠 نحوه کار الگوریتم

منطق اصلی برنامه سه مرحله دارد:

### ۱. بارگذاری و پیش‌پردازش

هنگام mount شدن کامپوننت، فایل `words.txt` یک‌بار خوانده می‌شود و:

- کلمات trim می‌شوند
- خطوط خالی حذف می‌شوند
- کلمات تکراری با `Set` حذف می‌شوند
- کلمات بر اساس **طول** در `buckets` گروه‌بندی می‌شوند: `{ 2: [...], 3: [...], ... }`

این Bucketing باعث می‌شود هنگام جستجو فقط به کلمات با طول درست نگاه کنیم و بقیه نادیده گرفته شوند.

### ۲. شمارش حروف ورودی

از حروفی که کاربر وارد می‌کند یک `map` بسازیم که تعداد تکرار هر حرف را نگه می‌دارد:

```js
"ابا" → { "ا": 2, "ب": 1 }
```

### ۳. بررسی هر کلمه

برای هر کلمه در bucketهای مرتبط:

- یک کپی از `letterCounts` بگیر
- هر حرف کلمه را یکی‌یکی مصرف کن
- اگر حرفی موجود نبود یا تمام شده بود → کلمه رد می‌شود
- اگر همه حروف مصرف شدند → کلمه به نتایج اضافه می‌شود

## ⚡ بهینه‌سازی‌های اعمال‌شده

| بهینه‌سازی               | توضیح                                                     |
| ------------------------ | --------------------------------------------------------- |
| **Length Bucketing**     | جستجو فقط در بازه طولی مورد نظر انجام می‌شود              |
| **Set برای dedupe**      | حذف کلمات تکراری در زمان بارگذاری                         |
| **useMemo**              | شمارش حروف فقط با تغییر ورودی دوباره محاسبه می‌شود        |
| **setTimeout در search** | جلوگیری از بلاک شدن رابط کاربری هنگام رندر "در حال جستجو" |
| **CDN Vercel**           | فایل `words.txt` در لبه شبکه کش می‌شود                    |

## ☁️ استقرار روی Vercel

پروژه با یک کلیک روی Vercel قابل استقرار است:

```bash
npm i -g vercel
vercel
```

### نکات مهم

- فایل `words.txt` باید **کمتر از ۱۰ مگابایت** باشد تا در CDN ورسل کش شود. دیتاست معین به راحتی زیر این حد قرار می‌گیرد.
- اولین درخواست در هر منطقه جغرافیایی ممکن است کمی کندتر باشد (cold cache)، اما درخواست‌های بعدی از edge cache سرو می‌شوند.
